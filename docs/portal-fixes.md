## حرجة: لازم تتعمل الأول

### W2. بوابة الأدمن بترجع 500 بشكل عشوائي (محتمل)
- **اللي اتعمل:** الرجوع لـ Session mode (5432) مع `max: 3` و`statement_timeout` (`ff33101` و`778f722`). التعليق راح.
- **المشكلة دلوقتي:** بعد الديبلوي، الأدمن بيرجع 500 على أغلب الطلبات. حتى `countries` و`auth/me` مرة تشتغل ومرة لأ، وبوابة المغسلة شغالة عادي.
- **السبب المحتمل:**
  - في Session mode، كل اتصال من كل instance على Vercel بيمسك مكان في الـ pool (حوالي 15 لـ 20)، وكل instance بيفتح لحد 3 اتصالات.
  - وقت الاختبار كان فيه 16 اتصال مفتوح من Supavisor. فالـ pool بيتملى، والطلبات اللي بعده بترجع "max clients reached".
- **الحل:**
  - خلّوا `max: 1` لكل instance في Session mode، ومعاه `idle_timeout: 5`. الـ pipelining على اتصال واحد آمن في Session mode؛ التعليق كان بيحصل في Transaction mode بس.
  - أو على المدى الطويل: Transaction mode (6543) مع `pg` (node-postgres) Pool، لأنه مابيعملش pipelining.
  - راجعوا logs Vercel للأدمن وقت الـ 500، علشان نتأكد إن الرسالة "max clients".
  - من عندنا: هنكبّر Pool Size في إعدادات Supabase.
